# Лексическая структура языка Udav
Здесь описаны лексемы (токены) и принципы работы лексического анализатора языка Udav.

## Формат входных файлов.
Лексический анализатор принимает текстовые файлы только в кодировке UTF-8. UTF-8 BOM в начале файла игнорируется. Если файл закодирован неверно, то анализатор выдаёт ошибку.

### Согласованность концов строк
Анализатор считывает файлы, в котором используется лишь один вид концов строк: LF, CRLF или CR. Анализатор определяет вид концов строк по первой строке файла. Если потом ему встречается другой конец строки, то анализатор аварийно завершает разбор файла.

**"Конец строки"** ниже в данном документе &mdash; это символы конца строки, которые используются в разбираемом файле. 

### Последняя строка файла
Если в последней непустой строке файла отсутствует конец строки, то анализатор автоматически добавляет его. В случае, если файл пустой, конец строки не добавляется.

## Регистрозависимость
Лексический анализатор везде, где это заранее не оговорено, учитывает регистр букв Unicode. Из этого следует, что, например, `foobar` и `FooBar` &mdash; это разные идентификаторы.

## Ключевые слова и идентификаторы
Ключевые слова состоят из букв `a-z`. Идентификатор (symbol на английском) состоит из символов `a-zA-Z0-9`.

Каждому ключевому слову сопоставляется токен. Ниже представлена таблица, показывающая эту связь.

| Ключевое слово | Токен  |
|:---------------|:-------|
| `fun`          | Fun    |
| `return`       | Return |
| `pass`         | Pass   |
| `let`          | Let    |
| `if`           | If     |
| `elif`         | ElseIf |
| `else`         | Else   |
| `while`        | While  |

Если строка соответствует и идентификатору, и какому-либо ключевому слову, то анализатор распознаёт её как *ключевое слово*.

## Литералы
### Целочисленный литерал
Целочисленный литерал состоит из цифр от 0 до 9. Этот литерал преобразуется анализатором в токен IntegerLiteral.

Примеры:
```
123
007
1234567890
```

### Строковый литерал
Строковый литерал начинается и заканчивается символом `"`. Внутри кавычек допускаются:
- любые символы Unicode, кроме LF, CR, `"` и `\`
- Escape-последовательности

Таблица допустимых escape-последовательностей представлена ниже.

| Последовательность | Символ Unicode |
|:-------------------|:---------------|
| `\\`               | `\`            |
| `\"`               | `"`            |
| `\n`               | LF             |
| `\r`               | CR             |
| `\t`               | TAB            |
| `\0`               | NUL            |

Строковый литерал преобразуется анализатором в токен StringLiteral.

## Комментарии
Любой комментарий преобразуется анализатором в токен Comment.

### Однострочный комментарий
Однострочный комментарий начинается с символа `#` и заканчивается концом строки. Сам конец строки не является частью токена комментария. Содержимое комментария может состоять из любых символов Unicode.

Конец строки в комментарии не поглощается анализатором, а преобразуется в токен NewLine. Например, текст
```
# I ❤️ Udav<line break><line break>
```
будет преобразован в следующую последовательность токенов
```
Comment "# I ❤️ Udav"
NewLine
NewLine
```

### Многострочный комментарий
Многострочный комментарий начинается с `#[` и заканчивается `]#`. Содержимое комментария может состоять из любых символов Unicode.

Анализатор поддерживает вложенные многострочные комментарии. Например, текст
```
#[
  Foo #[ Bar ]#
]#
```
будет преобразован в
```
Comment "#[<line break>  Foo #[ Bar ]#<line break>]#"
```

## Конец строки
Конец строки распознаётся анализатором как токен NewLine.
