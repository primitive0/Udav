# Лексическая структура языка Udav
Здесь описаны лексемы (токены) и принципы работы лексического анализатора языка Udav.

## Формат входных файлов
Лексический анализатор принимает текстовые файлы только в кодировке UTF-8. UTF-8 BOM в начале файла игнорируется. Если файл закодирован неверно, то анализатор выдаёт ошибку.

## Концы строк
Анализатор считывает файлы, в которых могут использоваться разные виды последовательностей концов строк: LF, CRLF и CR. Анализатор распознаёт все три последовательности концов строк одинаково. 

Последовательность CRLF должна распознаваться *жадно*.

**"Конец строки"** ниже в данном документе &mdash; это любая последовательность конца строки.

### Последняя строка файла
Если в файле в последней строке, содержащей что-либо кроме пробелов, отсутствует конец строки, то анализатор добавляет его неявно. В случае, если файл пустой, конец строки не добавляется.

## Регистрозависимость
Лексический анализатор везде, где это заранее не оговорено, *учитывает* регистр букв Unicode.

## Пробельные символы
Пробелы не в начале строки, вне строковых литералов и комментариев игнорируются и служат только для разделения токенов.

**Виртуальный токен** &mdash; это токен, который может появляться в потоке токенов без непосредственного соответствия отдельной части текста или соответствовать нескольким частям текста одновременно (например, разным вариантам конца строки или неявно добавленному концу файла).

## Ключевые слова и идентификаторы
### Ключевые слова
Ключевые слова состоят из букв `a-z`.

Каждому ключевому слову сопоставляется токен. Ниже представлена таблица, показывающая эту связь.

| Ключевое слово | Токен    |
|:---------------|:---------|
| `fun`          | Fun      |
| `return`       | Return   |
| `pass`         | Pass     |
| `let`          | Let      |
| `if`           | If       |
| `elif`         | Elif     |
| `else`         | Else     |
| `while`        | While    |
| `break`        | Break    |
| `continue`     | Continue |
| `false`        | False    |
| `true`         | True     |
| `null`         | Null     |

### Идентификаторы
Идентификатор (Symbol) состоит из символов `a-zA-Z0-9_`, но первый символ идентификатора не может быть цифрой.

Если строка соответствует и идентификатору, и какому-либо ключевому слову, то анализатор распознаёт её как *ключевое слово*.

| `\|\|` | Or               |

| `&`    | BitwiseAnd       |

| `>>`   | RightShift       |

| `=`    | Assign           |

| `%=`   | ModuloAssign     |
| `**=`  | PowerAssign      |
| `\|=`  | BitwiseOrAssign  |
| `&=`   | BitwiseAndAssign |
| `^=`   | BitwiseXorAssign |
| `>>=`  | RightShiftAssign |
| `<<=`  | LeftShiftAssign  |

Токены-операторы распознаются *жадно*. Это означает, что анализатор сначала пытается сопоставить самый длинный токен-оператор. Например, текст
```
a<<=b
```
будет распознан как
```
Symbol "a"
LeftShiftAssign
Symbol "b"
```
а не как
```
Symbol "a"
LeftShift
Assign
Symbol "b"
```

## Литералы
### Целочисленный литерал
Целочисленный литерал состоит из цифр от 0 до 9. Этот литерал преобразуется анализатором в токен IntegerLiteral.

Примеры:
```
123
007
1234567890
```

### Строковый литерал
Строковый литерал начинается и заканчивается символом `"`. Внутри кавычек допускаются:
- любые символы Unicode, кроме LF, CR, `"`
- Escape-последовательность `\"`, которая не закрывает строковый литерал

Строковый литерал преобразуется анализатором в токен StringLiteral.

Например, текст
```
"Hello, world!"
"String literal looks like this: \"String literal\""
"A \ (backslash)."
```
будет преобразован в следующую последовательность токенов
```
StringLiteral "\"Hello, world!\""
StringLiteral "\"String literal looks like this: \\\"String literal\\\"\""
StringLiteral "\"A \\ (backslash).\""
```

*Предполагается, что анализ escape-последовательностей проводится в синтаксическом анализаторе.*

## Комментарии
Комментарий преобразуется анализатором в токен Comment.

Комментарий начинается с символа `#` и заканчивается концом строки. Сам конец строки не является частью токена комментария. Содержимое комментария может состоять из любых символов Unicode.

Конец строки в комментарии не поглощается анализатором, а преобразуется в токен NewLine. Например, текст
```
# I ❤️ Udav<line break><line break>
```
будет преобразован в следующую последовательность токенов
```
Comment "# I ❤️ Udav"
NewLine
NewLine
```

## Конец строки
Конец строки распознаётся анализатором как токен NewLine. Токен NewLine считается *виртуальным*.

## Токены Indent и Dedent
Токены Indent и Dedent генерируются в зависимости от количества пробелов перед первым токеном на строке.

### Алгоритм генерации Indent и Dedent
1. Создать стек уровней отступов с одним элементом 0.
2. Прочитать следующую строку.
3. Если в строке содержатся только пробелы, комментарий или/и конец строки, то перейти на шаг 5.
4. Посчитать кол-во пробелов до первого иного символа. Назовём это число *уровнем*.
    1. Если *уровень* равен элементу на верху стека, то ничего не делать.
    2. Если *уровень* больше, то сгенерировать токен Indent и добавить уровень в стек.
    3. Если *уровень* меньше, то удалять элементы из стека и на каждое удаление генерировать токен Dedent, пока *уровень* не станет больше или равен верху стека.
        1. Если *уровень* больше верха стека, то прервать анализ с ошибкой "Несовместимый Dedent".
5. Проанализировать оставшееся содержимое строки.
6. Вернуться на шаг 2, если есть ещё строки.
7. Удалить все уровни из стека кроме нулевого, при каждом удалении генерировать токен Dedent.

Например, текст (`.` в начале &mdash; это пробелы)
```
fun main():
····let x = 1
# комментарий верхнего уровня
····if x:
········let y = 2
····let z = 3
let w = 4
```
будет преобразован в следующую последовательность токенов
```
Fun
Symbol "main"
ParenOpen
ParenClose
Colon
NewLine

Indent
Let
Symbol "x"
Assign
IntegerLiteral "1"
NewLine

Comment "# комментарий верхнего уровня"
NewLine

If
Symbol "x"
Colon
NewLine

Indent
Let
Symbol "y"
Assign
IntegerLiteral "2"
NewLine

Dedent
Let
Symbol "z"
Assign
IntegerLiteral "3"
NewLine

Dedent
Let
Symbol "w"
Assign
IntegerLiteral "4"
NewLine

EOF
```

## Токен EOF
Когда файл заканчивается, анализатор добавляет в последовательность токенов токен EOF.

### Порядок генерации токенов NewLine, Dedent и EOF в конце файла
В конце файла сначала добавляется токен NewLine, если он [необходим](#последняя-строка-файла), потом генерируются оставшиеся токены Dedent, а в самом конце появляется EOF.

Например, текст (концы строк обозначены явно)
```
fun main():<line break>
    io.println("foo")
```
будет преобразован в следующую последовательность токенов
```
Fun
Symbol "main"
ParenOpen
ParenClose
Colon
NewLine

Indent
Symbol "io"
Dot
Symbol "println"
ParenOpen
StringLiteral "\"foo\""
ParenClose

NewLine
Dedent
EOF
```
